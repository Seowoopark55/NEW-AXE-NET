# AXE NET → NEW AXE NET 기능 패리티 기준

NEW AXE NET은 기존 AXE NET 기능을 다시 발명하지 않습니다.
기존 AXE NET의 화면 흐름과 운영 규칙을 기능 명세로 사용하고, NEW에서는 Supabase-first 구조와 코드 분리/권한 설계만 개선합니다.

## 공금관리 기본 구조

1. 월별현황
2. 공금납부
3. 내 제출
4. 검수대기 (관리자)
5. 공금내역 (관리자)
6. 잔액점검 (관리자)
7. 요율관리 (관리자)
8. 면제관리 (관리자)
9. 정합성점검 (관리자)
10. 멤버관리 (관리자)

## 공금납부 패리티

기존 AXE NET 기준 흐름:

- 사이트 로그인 사용자를 제출자로 자동 사용
- 대상 월/주차 확인
- 공용계좌 / 회사잔고 / 분할납부
- 총 납부금액
- 증빙 스크린샷
- 메모
- 제출 → 검수대기 → 승인 시 원장 반영

v1.11.0 반영:

- 기존 AXE NET 닉네임/비밀번호 로그인 브리지
- Discord 숫자 ID 직접 입력 제거
- 로그인 멤버 자동 본인확인
- 관리자 Supabase Auth 계정도 연결 멤버 자동확인
- 공용계좌 / 회사잔고 납부 방식 선택
- 납부금액 / 증빙 링크 / 메모
- 내 제출 자동 조회

후속 패리티:

- 증빙 스크린샷 붙여넣기/파일 업로드
- 분할납부
- 관리자 대리제출
- 제출 수정/취소 정책
- 기존 AXE NET 검수 카드 수준의 상세 UI

## 작업 원칙

- 화면 하나를 만들기 전에 기존 AXE NET 구현을 먼저 확인한다.
- 기존 기능이 있으면 NEW에서 임의의 대체 UX를 만들지 않는다.
- 누적 CSS 덧붙임보다 해당 모듈의 기존 스타일 블록을 정리/교체한다.
- 브라우저에 service role 키나 Discord 숫자 ID를 노출하지 않는다.
- 관리자 쓰기는 Supabase Auth + RLS, 일반 멤버의 과도기 로그인은 서버 세션 브리지로 처리한다.

# AXE NET FUND REBASE 1.0

## 기준
기존 AXE NET의 최신 공금 운영 화면과 동작을 AXE NET의 **기능·UI 명세서**로 사용한다.

NEW에서 자유롭게 바꿀 수 있는 것은 내부 구현이다.
- 모듈 분리
- Supabase RPC / RLS
- 상태관리
- 중복 실행 방지
- 테스트·유지보수 구조

기존과 다르게 만들 경우에는 단순 취향이 아니라 명확한 사용성/기술상 이유가 있어야 한다.

## 레이아웃
- 전체 콘텐츠 기준폭: 1280px
- 남는 가로 공간: 좌우 균등
- 좁은 관리화면: 화면 왼쪽에 붙이지 않고 자체 max-width로 중앙정렬
- 작은 데이터셋: 빈 공간을 채우기 위해 카드/표를 강제로 늘리지 않음
- 표는 화면 폭을 나눠 먹는 `1fr`보다 실제 정보량에 맞는 열 폭을 우선

## 공금 정보 우선순위
1. 공용계좌
2. 검수대기·보류
3. 선택월 승인
4. 활성 면제

회사잔고는 필요한 화면에서 보조 정보로 유지한다.

## 공금 탭
일반 사용자:
- 월별현황
- 공금납부
- 내 제출

관리자 추가:
- 검수대기
- 공금내역
- 잔액점검
- 요율관리
- 면제관리
- 정합성점검
- 멤버관리

## 검수대기
기존 AXE NET 작업 흐름을 기준으로 한다.
- pending + hold를 한 큐에 표시
- 오래된 신청부터 확인
- 전체 선택
- 선택 일괄승인
- 승인 / 보류 / 반려
- 검수 메모/반려 사유
- 증빙 보기

## 공금내역
최신 AXE NET의 월별 내역 화면을 기준으로 한다.
- 월 선택
- 지출/수입 등록
- 검색창 없음
- 이름 / 구분 / 계좌 선택 필터
- 필터 초기화
- `날짜 / 구분 / 항목 / 관련자 / 월·주차 / 금액 / 방향 / 계좌 / 증빙 / 메모 / 관리` 11열
- 직접기입 / 승인반영 구분

NEW의 안전 삭제/복구와 수정 모달은 기존 기능을 해치지 않는 관리 보강으로 유지한다.

## 의도적으로 유지하는 NEW 차이
- 월별현황 마지막 `미납 합계` 열은 사용자의 기존 제거 요청에 따라 복구하지 않는다.
- 사용자/관리자 본인 확인은 수동 Discord ID 입력이 아니라 NEW 로그인 세션 연결 구조를 사용한다.
- DB는 Google Sheet가 아니라 Supabase를 authoritative source로 사용한다.
- 멤버 원본을 공금 테이블에 다시 복제하지 않고 `members` + `fund_member_settings`로 분리한다.

## 기간 면제
기존 AXE NET 동작을 복원한다.
- 시작 월/주차 → 종료 월/주차
- 겹치는 활성 면제 차단
- pending / hold / approved 신청이 있는 기간 차단
- 기간 전체 해제

NEW DB에서는 기존 live status engine을 건드리지 않기 위해 각 주차를 개별 `fund_exemptions` 행으로 저장하고, 동일 등록 범위를 `range_key`로 묶는다.

## CSS 소유권
리베이스 시 구형 `main.css`의 공금 전용 블록을 제거한다.

v1.24 구조 리베이스 이후 공금 UI canonical owner는 아래 세 파일이다.
- `src/modules/fund/fund.css` — 공통/사용자 workflow
- `src/modules/fund/operations-console.css` — 공금 shell / 월별현황 / 공금내역 / 검수대기
- `src/modules/fund/views/admin.css` — 잔액 / 요율 / 면제 / 정합성 / 공금 멤버관리

`main.css`는 공금 selector를 소유하지 않는다. 같은 문제를 다시 만들 수 있는 버전별 `.fund-*` override 누적은 금지한다. 상세 기준은 `AXE_STYLE_REBASE_1.0.md`를 따른다.

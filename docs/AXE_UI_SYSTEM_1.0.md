# AXE UI SYSTEM 1.0

NEW AXE NET의 UI/UX 기준서는 기존 AXE NET입니다.
NEW에서 화면마다 임의의 글자 크기/간격/행 높이를 새로 정하지 않습니다.

## 1. 기준 수치

기존 AXE NET 공금 UI에서 추출한 핵심 기준:

| 항목 | 기준 |
|---|---:|
| 전체 콘텐츠 최대폭 | 1280px |
| 페이지 제목 | 25px |
| 카드/폼 제목 | 15~16px |
| 일반 본문/테이블 셀 | 12.5px |
| 입력/버튼 글자 | 13px |
| 라벨 | 12px |
| 메타/보조정보 | 11~11.5px |
| 입력/select 높이 | 38px |
| 기본 버튼 높이 | 36px |
| 상태칩 높이 | 24px |
| 상태칩 최소폭 | 44px |
| 기본 카드 radius | 13px |
| 일반 패널 radius | 15~16px |
| 공금 표 셀 padding | 9px 8px |
| 월별현황 멤버 열 | 170px |
| 월별현황 주차 열 | 92px |

## 2. NEW 구현 규칙

- 수치는 `src/styles/axe-ui-system.css` 변수에서 관리한다.
- 새 모듈은 위 토큰을 재사용한다.
- 화면이 넓어져도 테이블 열을 `1fr`로 무한 확장하지 않는다.
- 데이터 표는 내용에 필요한 폭을 우선하고, 작은 화면에서만 가로 스크롤한다.
- 글씨를 7~9px까지 축소해서 컴팩트하게 보이게 하는 방식은 사용하지 않는다.
- 컴팩트함은 작은 글씨가 아니라 `열 폭 / gap / padding / 정보 우선순위`로 만든다.
- 상태칩, 버튼, input/select 높이는 화면마다 다시 만들지 않는다.
- 기존 AXE NET보다 고급스러운 배경/테두리/hover는 허용하지만 정보밀도와 가독성 기준은 AXE NET을 벗어나지 않는다.

## 3. 공금 화면 적용

v1.16.0에서 아래를 AXE UI SYSTEM으로 통일:

- 월별현황
- 공금납부 / 내 제출 / 검수대기 공통 컨트롤
- 공금내역 테이블
- 잔액점검
- 요율관리
- 면제관리
- 정합성점검
- 멤버관리

## 4. 이후 개발 원칙

기능 구현 → UI 압축의 2단계 작업을 하지 않는다.
처음 렌더링부터 AXE UI SYSTEM 토큰과 공통 폭 규격을 사용한다.

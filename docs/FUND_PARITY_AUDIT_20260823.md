# AXE NET → AXE NET 공금 패리티 감사

기준일: 2026-08-23  
대상 버전: AXE NET v1.22.0

## 결론

기존 AXE NET의 공금관리 10개 탭을 기능 기준으로 대조했다. v1.22.0에서는 화면 미세조정보다 **운영 동작과 데이터 판정 차이**를 우선 정리했다.

가장 중요한 차이는 월별현황의 상태 판정이었다. 기존 AXE NET은 승인/원장 금액이 기준 공금보다 적으면 `부족`, 처리 중 신청은 `검수대기`, 반려만 남은 회차는 `반려`로 구분했다. NEW는 기존에 활성 납부 원장이 1원이라도 있으면 `완료`로 보던 부분이 있어 이를 수정했다.

## v1.22.0 핵심 수정

### 1. 상태 엔진

상태 우선순위를 다음과 같이 통일했다.

`가입 전/예정 → 면제 → 완료/부족 → 검수대기 → 반려 → 미납`

- 활성 납부 합계가 기준액보다 작으면 `부족`
- pending 또는 hold 신청이 있으면 `검수대기`
- 활성 납부/처리 중 신청이 없고 rejected 신청이 있으면 `반려`
- 월별 미납 합계에는 `미납 + 부족 + 반려`를 포함

### 2. 반려 회차 재제출

반려 상태를 월별현황에 보여주더라도 실제 운영에서는 다시 제출할 수 있어야 한다. 따라서 공금납부 화면의 제출 가능 회차를 `미납 또는 반려`로 정의하고 pending/hold만 차단한다.

### 3. 제출 후 이동

기존 AXE NET과 같이 제출 성공 직후 `내 제출` 탭으로 이동한다. 방금 올린 증빙과 검수대기 상태를 즉시 확인하는 흐름으로 복원했다.

### 4. 기준일 보정 일관성

`fund_member_settings.join_date_override`가 live status뿐 아니라 멤버 개인 공금 프로필의 기간 목록에도 동일하게 적용되도록 `get_my_fund_profile`을 보강했다.

### 5. 정합성점검

기존 4개 점검에 `승인 신청 ↔ 활성 원장 금액 불일치`를 추가했다.

안전하게 자동화할 수 있는 작업만 UI 버튼으로 제공한다.

- 승인 신청은 있으나 원장이 없음 → `원장 복구`
- 원장 금액이 기준으로 판단됨 → `신청 금액 맞추기`
- 신청 금액이 기준으로 판단됨 → `원장 금액 맞추기`
- 이미 납부 원장이 있는데 pending/hold 신청이 남음 → `충돌 신청 반려`

모든 보정은 `fund_admin_audit_log`에 기록한다.

## 의도적으로 기존 AXE NET과 다르게 유지하는 부분

- 월별현황 우측 `미납 합계` 열은 이전 NEW 작업에서 제거하기로 한 기준을 유지한다.
- 상단 주요 KPI는 회사잔고보다 **공용계좌 잔액**을 우선한다.
- 회원 원본을 공금 멤버 테이블에 다시 복제하지 않고 `members + fund_member_settings` 구조를 유지한다.
- 정합성점검에서 원장/신청을 물리 삭제하는 파괴적 자동복구는 제공하지 않는다. 삭제가 필요하면 기존 안전 삭제/감사 로그 경로를 사용한다.
